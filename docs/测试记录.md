## 8. CPU 100 °C 的交叉判断

- Intel i5-12400F 官方 TjMax 为 100 °C；Package 温度与 Core Max 均多次达到 100 °C。
- DTS 数据内部一致：例如核心 93 °C 对应距 TjMax 7 °C，核心 100 °C 对应距 TjMax 0 °C。
- 同期 CPU 总负载仅约 12–14%，封装功耗约 28–32 W，仍贴近 TjMax，不符合正常散热表现。
- SuperIO 暴露的 7 个风扇转速通道均为 0 RPM，风扇控制值却在 60–100%。
- Windows ACPI 热区约 27.85 °C 是机箱 / 主板热区，不是 CPU 核温，不能用来否定 DTS；WMI 仅提供标称频率和负载，也没有核心温度。
- 结论：现有证据高度支持“真实高温 / 散热异常”，不是单一传感器解析错误；仍需 BIOS 或独立监控工具交叉确认，建议优先检查 CPU 风扇 / 水冷泵、供电、散热器固定和硅胶状态。
- 在独立交叉验证完成前，不把 100 °C 改写成正常值，也不做温度上限“美化”。

用户指出去掉 Windows 原生标题栏后，最大化和关闭按钮消失。本轮只在 HUD 头部扩展，不改动原有语言、置顶、隐藏到托盘和拖动逻辑。

实现范围：

- `dashboard.html` 的 `window-actions` 保持原顺序，新增 `maximize-button`（最大化 / 还原动态图标）和 `close-button`（关闭并退出）；关闭按钮 hover 使用红色危险态。
- 新增 `i-maximize`、`i-restore`、`i-close` 三个内联 SVG symbol；新增 `maximize.tooltip` / `restore.tooltip` / `close.tooltip` 中英文案，沿用语言切换更新 tooltip 与 `aria-label`。
- 页面新增 `toggle-maximize` / `close-window` 消息；宿主 `OnWebMessageReceived` 处理二者，`SendHostSettings` 下发 `maximized`，`OnStateChanged` 在最大化 / 还原后重新下发，页面用 `setMaximized()` 切换图标、文案和 `aria-pressed`。
- 最大化在 `WindowStyle=None + WindowChrome` 下会默认覆盖任务栏；宿主加入 `WM_GETMINMAXINFO` 处理，按当前显示器 `rcWork` 设置最大化位置和尺寸，并动态把 `ResizeBorderThickness` 在最大化时设为 0、还原时设为 6。
- 关闭路径不再在 `OnClosing` 同步调用 `WebView.Dispose()`（WebView2 同步释放会阻塞窗口关闭）；`OnExit` 的 telemetry 清理改为后台任务并最多等待 2 秒，避免采集线程慢时进程无法退出。
